# ระบบแปลภาษามือไทยเป็นข้อความ

โปรเจคเพื่อการศึกษา — อ่านท่ามือจากกล้องแล้วแปลออกมาเป็นข้อความภาษาไทยแบบเรียลไทม์
มีสองรุ่นที่ใช้ข้อมูลร่วมกันได้:

| รุ่น | อยู่ที่ | เหมาะกับ |
|------|---------|----------|
| **คอมพิวเตอร์** (Python) | `src/` | เก็บข้อมูลจำนวนมาก ทดลองปรับโมเดล ดูรายงานผลละเอียด |
| **มือถือ** (PWA) | `app/` | ใช้งานจริงนอกสถานที่ ติดตั้งลงหน้าจอหลัก ทำงานออฟไลน์ |

ทั้งสองรุ่นใช้ feature vector 133 ค่าที่คำนวณด้วยวิธีเดียวกัน จึงเก็บข้อมูลที่ฝั่งไหน
แล้วย้ายไปอีกฝั่งได้ ดู [แอปมือถือ](app/README.md) และหัวข้อ
[แชร์ข้อมูลระหว่างสองรุ่น](#แชร์ข้อมูลระหว่างสองรุ่น)

พัฒนาต่อยอดแนวคิดจาก [Sign-Language-detection](https://github.com/PriyanshChhabra0316/Sign-Language-detection)
แต่เปลี่ยนสถาปัตยกรรมภายในใหม่ทั้งหมด เหตุผลอยู่ในหัวข้อ
[ต่างจากโปรเจคต้นแบบอย่างไร](#ต่างจากโปรเจคต้นแบบอย่างไร)

```
กล้องเว็บแคม
     |
     v

     |

     |

   ข้อความภาษาไทย
```

## การติดตั้ง

ต้องมี `.venv` อยู่ในรากโปรเจค เพราะ `run.bat` เรียก `.venv\Scripts\python.exe` ตรง ๆ

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

> **เรื่องเวอร์ชัน Python**
> ทดสอบแล้วว่าใช้ได้ถึง Python 3.14 (mediapipe 0.10.35 แจกเป็น wheel แบบ
> `py3-none-win_amd64` จึงติดตั้งได้ทุกรุ่นของ Python 3) เอกสารของ MediaPipe
> เคยระบุว่ารองรับถึง 3.12 เท่านั้น ซึ่งไม่เป็นจริงกับรุ่นนี้แล้ว
> ถ้าเจอปัญหาให้ลองสร้าง venv จาก Python 3.12 ด้วย `py -3.12 -m venv .venv`

ตรวจว่าติดตั้งครบหรือยัง (ไม่ต้องใช้กล้อง):

```bash
run selftest
```

ควรขึ้น `ผ่าน 13 ข้อ, ไม่ผ่าน 0 ข้อ`

ตรวจว่ากล้องและการตรวจจับมือทำงานได้ (เปิดกล้อง แต่ปิดเองอัตโนมัติ ไม่มีหน้าต่างให้กด):

```bash
run camtest
```

จะนับถอยหลัง 5 วินาทีให้เตรียมยกมือ แล้วทดสอบ 10 วินาที สุดท้ายรายงาน FPS
และอัตราการตรวจเจอมือ พร้อมบันทึกภาพตัวอย่างที่วาดโครงมือไว้ที่
`data/camtest_snapshot.jpg`

**อัตราการตรวจเจอมือควรได้เกิน 90%** ถ้าได้ต่ำกว่านี้ให้เพิ่มแสงหรือขยับเข้าใกล้กล้อง
ก่อนไปเก็บข้อมูลจริง ไม่งั้นจะเสียเวลาเก็บข้อมูลคุณภาพต่ำ

ปรับเวลาได้:

```bash
run camtest --countdown 10 --seconds 20
```

## วิธีใช้งาน — 3 ขั้นตอน

### ขั้นที่ 1: เก็บข้อมูลท่ามือ

```bash
run collect
```

| ปุ่ม | ความหมาย |
|------|-----------|
| `SPACE` | เก็บ 1 ตัวอย่าง |
| `C` | เปิด/ปิดโหมดเก็บต่อเนื่อง |
| `N` / `P` | ไปคำถัดไป / คำก่อนหน้า |
| `D` | ลบตัวอย่างล่าสุดของคำปัจจุบัน |
| `Q` | ออก |

**เคล็ดลับสำคัญที่สุดของทั้งโปรเจค:** ระหว่างเปิดโหมดต่อเนื่อง ให้ค่อย ๆ
หมุนข้อมือ เอียงมือ ขยับเข้า-ออกจากกล้อง และย้ายมือไปมุมต่าง ๆ ของเฟรม
ถ้าเก็บภาพนิ่งสนิท 200 ภาพ โมเดลจะรู้จักท่านั้นแค่มุมเดียวและใช้งานจริงไม่ได้

แนะนำคำละ **150–200 ตัวอย่าง** และควรให้ทุกคำมีจำนวนใกล้เคียงกัน

ข้อมูลถูกบันทึกลง `data/landmarks.csv` แบบต่อท้ายทันทีทุกตัวอย่าง
หยุดกลางคันแล้วมาเก็บต่อวันหลังได้ ข้อมูลไม่หาย

### ขั้นที่ 2: เทรนโมเดล

```bash
run train
```

ใช้เวลาไม่กี่วินาที ผลลัพธ์:
- `models/classifier.joblib` — โมเดลที่เทรนแล้ว
- `docs/training_report.txt` — รายงานความแม่นยำ + confusion matrix

ตัวเลือกเพิ่มเติม:

```bash
run train --model rf
```

```bash
run train --no-augment
```

### ขั้นที่ 3: แปลภาษามือเป็นข้อความ

```bash
run translate
```

| ปุ่ม | ความหมาย |
|------|-----------|
| `SPACE` | เว้นวรรค |
| `BACKSPACE` | ลบคำล่าสุด |
| `C` | ล้างข้อความทั้งหมด |
| `S` | บันทึกข้อความลง `data/transcripts.txt` |
| `Q` | ออก |

## การปรับแต่ง

แก้ที่ [`config.py`](config.py) ไฟล์เดียวพอ ค่าที่ปรับบ่อยที่สุด:

| ค่า | ค่าเริ่มต้น | ความหมาย |
|-----|-----------|-----------|
| `ACTIVE_LABELS` | `LABELS_TH_WORDS` | ชุดคำที่จะสอน สลับเป็น `LABELS_TH_ALPHABET` (ก-ฮ) หรือเขียนลิสต์เองได้ |
| `CAMERA_INDEX` | `0` | ถ้ากล้องไม่ขึ้น ลองเปลี่ยนเป็น `1` หรือ `2` |
| `CONFIDENCE_THRESHOLD` | `0.75` | ยิ่งสูงยิ่งเข้มงวด ทายผิดน้อยลงแต่ต้องทำท่าชัดขึ้น |
| `STABLE_FRAMES_REQUIRED` | `8` | ต้องค้างท่านิ่งกี่เฟรมถึงจะรับคำ ยิ่งมากยิ่งไม่รับคำมั่ว แต่ต้องค้างท่านานขึ้น |
| `COOLDOWN_SEC` | `1.0` | ช่วงพักก่อนรับคำเดิมซ้ำ |
| `MAX_HANDS` | `2` | ภาษามือไทยหลายคำใช้สองมือ |

> **เปลี่ยน `ACTIVE_LABELS` แล้วต้องเก็บข้อมูลและเทรนใหม่** เพราะโมเดลรู้จักเฉพาะคำที่เคยเห็น

## แอปมือถือ

โฟลเดอร์ [`app/`](app/README.md) คือแอปรุ่นมือถือ เป็น PWA ที่ติดตั้งลงหน้าจอหลักได้
ใช้ได้ทั้ง Android และ iPhone มีครบทั้งโหมดบันทึกท่า โหมดเทรน และโหมดแปล
ทุกอย่างทำงานบนเครื่องผู้ใช้ ไม่ส่งข้อมูลออกนอกเครื่อง และใช้งานได้แม้ไม่มีอินเทอร์เน็ต

ทดสอบบนคอมพิวเตอร์ก่อน:

```bash
run serve
```

แล้วเปิด `http://localhost:8000` — วิธีติดตั้งลงมือถือจริงผ่าน GitHub Pages
และวิธีห่อเป็นไฟล์ APK อยู่ใน [`app/README.md`](app/README.md)

### แชร์ข้อมูลระหว่างสองรุ่น

คอมพิวเตอร์ → มือถือ (ได้ไฟล์ `data/signdata.json` ส่งเข้ามือถือแล้วกด "นำเข้าข้อมูล"):

```bash
run transfer export
```

มือถือ → คอมพิวเตอร์ (กด "ส่งออกข้อมูล" ในแอป แล้วส่งไฟล์กลับมา):

```bash
run transfer import data\signdata.json
```

ตรวจว่าโค้ดสองฝั่งยังคำนวณ feature ตรงกัน — **ต้องรันทุกครั้งที่แก้ `features.py`
หรือ `features.js`**:

```bash
run parity
```

คำสั่งนี้ตรวจสองขั้น: (1) ฟังก์ชันคำนวณ feature ให้ค่าตรงกันไหม และ (2) ทั้งเส้นทาง
ให้ค่าตรงกันไหม ขั้นที่สองสำคัญเพราะฝั่งคอมพิวเตอร์พลิกเฟรมด้วย `cv2.flip` ก่อนส่งเข้า
MediaPipe แต่ฝั่งมือถือส่งภาพดิบเข้าไป (พลิกกระจกด้วย CSS ตอนแสดงผลเท่านั้น)
MediaPipe จึงเรียกชื่อมือซ้าย-ขวาสลับกันระหว่างสองฝั่ง ฝั่งคอมพิวเตอร์แก้ด้วยการแปลง
เวกเตอร์กลับเป็น "คอนเวนชันกลาง" ผ่าน `build_canonical_feature_vector`
(อ่านรายละเอียดใน `src/features.py`)

### ข้อมูลที่เก็บไว้ก่อนเวอร์ชันนี้

ไฟล์ JSON มีเลขรุ่นกำกับ ทั้งสองฝั่งจึงแปลงให้อัตโนมัติตอนนำเข้าและแจ้งบนหน้าจอ

| รุ่นไฟล์ | ต่างจากตอนนี้อย่างไร | เวลานำเข้า |
|---------|---------------------|-----------|
| 1 | 128 มิติ + ฝั่งคอมพิวเตอร์ใช้คอนเวนชันมือแบบเก่า | ขยายมิติ + สลับคอนเวนชันให้ |
| 2 | 128 มิติ (ยังไม่มีท่อนคู่มือ) | ขยายมิติให้ |
| 3 | รุ่นปัจจุบัน 133 มิติ | ใช้ได้ทันที |

ส่วนแอปมือถือจะขยายข้อมูลที่เก็บไว้ในเครื่องให้เองตอนเปิดแอปครั้งแรกหลังอัปเดต
และทิ้งโมเดลเก่าที่รับ input คนละขนาดพร้อมแจ้งให้กดเทรนใหม่

**`data/landmarks.csv` ในเครื่องต้องสั่งแปลงเอง** เพราะไฟล์ CSV ไม่ได้บันทึกเลขรุ่นไว้:

```bash
run transfer convert-legacy
```

คำสั่งนี้ดูจำนวนคอลัมน์ในหัวตาราง แล้วขยายจาก 128 เป็น 133 มิติให้ถ้าจำเป็น
สั่งซ้ำได้ไม่มีผลข้างเคียง และสำรองไฟล์เดิมเป็น `.csv.bak` ให้ก่อนทุกครั้ง

ถ้าข้อมูลชุดนั้น**เก็บด้วยคอมพิวเตอร์ก่อนที่จะรวมคอนเวนชันมือซ้าย-ขวา** ให้เพิ่ม `--mirror`:

```bash
run transfer convert-legacy --mirror
```

ส่วนนี้ตรวจอัตโนมัติไม่ได้ ต้องอาศัยความจำของคุณเอง ถ้าใส่ผิดให้สั่ง `--mirror`
ซ้ำอีกครั้งเพื่อย้อนกลับ (การกลับด้านสองครั้งหักล้างกันเอง) ถ้าไม่แปลงแล้วเทรน
แบบเปิดการเพิ่มข้อมูลกลับด้าน (ค่าเริ่มต้น) โมเดลจะยังใช้ได้ แต่ `--no-augment`
จะแม่นยำตกอย่างอธิบายไม่ถูก

## ต่างจากโปรเจคต้นแบบอย่างไร

โปรเจคต้นแบบใช้แนวทาง **ครอปรูปมือแล้วเทรน CNN จากภาพ** ผ่าน Google Teachable Machine
ซึ่งเป็นแนวทางที่เข้าใจง่ายดี แต่รันบนเครื่องนี้ไม่ได้และมีข้อจำกัดหลายอย่าง

| หัวข้อ | โปรเจคต้นแบบ | โปรเจคนี้ |
|--------|---------------|-----------|
| ตรวจจับมือ | `cvzone` + `mp.solutions.hands` | MediaPipe Tasks API |
| สิ่งที่ป้อนให้โมเดล | รูปภาพ 300×300 พิกเซล | เวกเตอร์ 133 ค่าจาก landmark |
| การเทรน | Google Teachable Machine (บนเว็บ) | scikit-learn ในเครื่อง |

### เหตุผลทางเทคนิคสามข้อที่ต้องเปลี่ยน

1. **`cvzone` ใช้กับ MediaPipe รุ่นปัจจุบันไม่ได้แล้ว**
   MediaPipe ตั้งแต่รุ่น 0.10.3x ตัด API เดิม (`mp.solutions.hands`) ออกไป
   ยืนยันบนเครื่องนี้แล้ว: `mediapipe 0.10.35` ไม่มี `mp.solutions` และไม่มีโมดูล `mediapipe.python`
   โค้ดสอนเก่าที่ `import cvzone` จึงพังตั้งแต่บรรทัดแรก

2. **`cv2.putText` เขียนภาษาไทยไม่ได้**
   รองรับเฉพาะ ASCII ถ้าส่งภาษาไทยเข้าไปจะได้ `???` เรียงกัน
   จึงต้องมี `src/thai_text.py` ที่แปลงเฟรมเป็นภาพ Pillow แล้ววาดด้วยฟอนต์ไทยจริง

3. **โมเดล `.h5` จาก Teachable Machine เป็น Keras 2**
   โหลดกับ TensorFlow/Keras 3 รุ่นปัจจุบันไม่ได้ ต้อง pin เวอร์ชันเก่าค้างไว้
   ซึ่งไม่เหมาะกับโปรเจคที่ต้องใช้งานและพัฒนาต่อ

## ข้อจำกัดที่ควรรู้ (สำคัญสำหรับการเขียนรายงาน)

**ระบบนี้จำแนก "ท่ามือนิ่ง" เท่านั้น ยังอ่าน "การเคลื่อนไหว" ไม่ได้**

นี่เป็นข้อจำกัดเชิงสถาปัตยกรรม ไม่ใช่บั๊ก โมเดลตัดสินใจจากเฟรมเดียวโดด ๆ
จึงแยกท่าที่รูปมือเหมือนกันแต่ทิศทางการเคลื่อนไหวต่างกันไม่ออก

ผลกระทบต่อภาษามือไทย:
- **พยัญชนะ ก-ฮ** — ส่วนใหญ่เป็นท่านิ่ง ใช้ได้ดี แต่บางตัวมีการขยับประกอบ
- **คำพื้นฐาน** — หลายคำเช่น "สวัสดี" หรือ "ขอบคุณ" มีการเคลื่อนไหวเป็นส่วนสำคัญ
  ระบบจะจับได้แค่ "ท่าค้างที่เป็นจุดเด่นที่สุด" ของคำนั้น ซึ่งพอใช้งานได้ในระดับสาธิต
  แต่ไม่ใช่การแปลภาษามือที่ถูกต้องสมบูรณ์ตามหลักภาษาศาสตร์

ข้อจำกัดอื่น:
- ต้องเก็บข้อมูลเองทั้งหมด และโมเดลจะแม่นกับ *คนที่เก็บข้อมูล* มากที่สุด
  ถ้าอยากให้ใช้ได้กับหลายคน ต้องให้หลายคนช่วยกันเก็บ
- แสงน้อยมากหรือมือซ้อนทับกันจะทำให้ MediaPipe ตรวจจับพลาด
- ไม่ได้จับสีหน้าและท่าทางลำตัว ซึ่งเป็นส่วนหนึ่งของไวยากรณ์ภาษามือจริง

## แนวทางพัฒนาต่อ

เรียงจากง่ายไปยาก:

1. **เพิ่มคำ** — แก้ `ACTIVE_LABELS` แล้วเก็บข้อมูล + เทรนใหม่
2. **อ่าน `docs/training_report.txt`** — ดู confusion matrix ว่าคำคู่ไหนสับสนกัน แล้วเก็บข้อมูลคู่นั้นเพิ่ม
3. **เพิ่มเสียงพูด** — ต่อ text-to-speech ภาษาไทยเข้ากับข้อความที่แปลได้
4. **รองรับท่าเคลื่อนไหว** — เก็บ landmark เป็นลำดับ 30 เฟรมแทนเฟรมเดียว
   แล้วเปลี่ยนโมเดลเป็น LSTM หรือ 1D-CNN นี่คือก้าวที่ทำให้แปลคำที่มีการเคลื่อนไหวได้จริง
5. **เพิ่มข้อมูลใบหน้าและลำตัว** — เปลี่ยนไปใช้ MediaPipe Holistic
