# แอปมือถือ — แปลภาษามือไทยเป็นข้อความ

แอปนี้เป็น **PWA** (Progressive Web App) เปิดจากเบราว์เซอร์บนมือถือแล้วกด
"เพิ่มไปยังหน้าจอหลัก" จะได้ไอคอนและใช้งานเหมือนแอปทั่วไป ไม่ต้องลง Play Store
ใช้ได้ทั้ง Android และ iPhone

**ทุกอย่างทำงานบนเครื่องผู้ใช้ทั้งหมด** ทั้งการตรวจจับมือ การเทรน และการแปล
ไม่มีการส่งภาพหรือข้อมูลใด ๆ ออกไปที่เซิร์ฟเวอร์ และใช้งานได้แม้ปิดอินเทอร์เน็ต

---

## สามโหมดในแอป

| แท็บ | หน้าที่ | ใช้กล้อง |
|------|---------|----------|
| **บันทึก** | เปิดกล้อง ทำท่า พิมพ์ว่าท่านี้แปลว่าอะไร แล้วกดเก็บ | กล้องหน้า |
| **เทรน** | เทรนโมเดลจากข้อมูลที่เก็บไว้ ปรับค่า และรับส่งข้อมูล | ไม่ใช้ |
| **แปล** | ส่องกล้องไปที่ผู้ทำท่า อ่านคำแปลบนหน้าจอ ต่อเป็นประโยค | กล้องหลัง |

โหมดแปลมีปุ่มคัดลอกข้อความ และปุ่มอ่านออกเสียงภาษาไทย (ใช้เสียงสังเคราะห์ของเครื่อง)

---

## ทดสอบบนคอมพิวเตอร์ก่อน

```bash
run serve
```

แล้วเปิด `http://localhost:8000` กล้องจะใช้งานได้ปกติเพราะเบราว์เซอร์ถือว่า
`localhost` เป็นแหล่งที่ปลอดภัย

> **เปิดจากมือถือผ่านเลข IP ในวง LAN จะใช้กล้องไม่ได้** เบราว์เซอร์บังคับว่า
> ต้องเป็น `https` เท่านั้นถ้าไม่ใช่ `localhost` จึงต้องขึ้น GitHub Pages ก่อน

---

## ติดตั้งลงมือถือจริง — ผ่าน GitHub Pages

GitHub Pages ให้ `https` ฟรี ซึ่งเป็นเงื่อนไขที่ขาดไม่ได้ของการเปิดกล้องบนเว็บ

### ขั้นที่ 1 — เปิด Pages ในหน้าตั้งค่าของ repo

1. เข้า repo บน GitHub → แท็บ **Settings** → เมนูซ้าย **Pages**
2. หัวข้อ *Build and deployment* → **Source** เลือก `Deploy from a branch`
3. **Branch** เลือก `main` และโฟลเดอร์ `/ (root)` → กด **Save**
4. รอสัก 1–2 นาที

### ขั้นที่ 2 — เปิดบนมือถือ

เปิดเบราว์เซอร์บนมือถือไปที่ (แทน `<ชื่อผู้ใช้>` และ `<ชื่อ repo>` ของคุณ):

```
https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/app/
```

### ขั้นที่ 3 — เพิ่มลงหน้าจอหลัก

- **Android (Chrome)** — เมนูสามจุด → *เพิ่มไปยังหน้าจอหลัก* หรือ *ติดตั้งแอป*
- **iPhone (Safari)** — ปุ่มแชร์ → *เพิ่มไปยังหน้าจอโฮม*
  (ต้องใช้ Safari เท่านั้น Chrome บน iOS เพิ่มไม่ได้)

การเปิดครั้งแรกจะโหลดราว **19 MB** (ตัวประมวลผลและโมเดลตรวจจับมือ)
ควรทำตอนต่อ Wi-Fi หลังจากนั้นเปิดใช้แบบออฟไลน์ได้เลย

## แชร์ข้อมูลกับคอมพิวเตอร์

ทั้งสองฝั่งใช้ feature vector 128 ค่าที่คำนวณด้วยวิธีเดียวกัน (ตรวจสอบด้วย `run parity`)
จึงเก็บข้อมูลที่ฝั่งไหนก็ได้ แล้วย้ายไปอีกฝั่ง

**สิ่งที่แชร์คือชุดข้อมูล ไม่ใช่ตัวโมเดล** เพราะสองฝั่งใช้ไลบรารีคนละตัว
แต่ละฝั่งเทรนโมเดลของตัวเองจากข้อมูลชุดเดียวกันได้ผลใกล้เคียงกัน

### คอมพิวเตอร์ → มือถือ

```bash
run transfer export
```

ได้ไฟล์ `data/signdata.json` ส่งเข้ามือถือ (LINE, อีเมล, Google Drive)
แล้วในแอปไปที่แท็บเทรน → **นำเข้าข้อมูล**

### มือถือ → คอมพิวเตอร์

ในแอปไปที่แท็บเทรน → **ส่งออกข้อมูล** จะได้ไฟล์ JSON ส่งกลับมาที่คอมพิวเตอร์ แล้ว:

```bash
run transfer import data\signdata.json
```

เพิ่ม `--replace` ถ้าต้องการแทนที่ข้อมูลเดิมทั้งหมด (ระบบสำรองไฟล์เดิมให้อัตโนมัติ)

## ถ้าอยากได้เป็นไฟล์ APK จริง

PWA ห่อเป็น APK ได้ด้วย **TWA** (Trusted Web Activity) โดยไม่ต้องเขียนโค้ดใหม่:

1. ติดตั้ง Node.js แล้วรัน `npx @bubblewrap/cli init --manifest https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/app/manifest.webmanifest`
2. ตอบคำถามตามที่ถาม แล้วรัน `npx @bubblewrap/cli build`
3. ได้ไฟล์ `app-release-signed.apk` ติดตั้งลงเครื่อง Android ได้

ข้อดีคือโค้ดชุดเดียว แก้ที่เดียว ทั้งเว็บและ APK อัปเดตตามกันทันที
ข้อจำกัดคือใช้ได้เฉพาะ Android ส่วน iPhone ยังต้องใช้วิธี "เพิ่มไปยังหน้าจอโฮม"

## โครงสร้างไฟล์

```
app/
├── index.html                  โครงหน้าจอทั้งหมด
├── manifest.webmanifest        ข้อมูลแอปสำหรับติดตั้งลงหน้าจอหลัก
├── sw.js                       service worker ทำให้ทำงานออฟไลน์ได้
├── css/style.css
├── js/
│   ├── app.js                  ตัวควบคุมหลัก ผูกทุกส่วนเข้าด้วยกัน
│   ├── features.js             แปลง landmark เป็นเวกเตอร์ 128 ค่า  <- ต้องตรงกับ src/features.py
│   ├── mlp.js                  โครงข่ายประสาทเทียม เขียนด้วย JS ล้วน
│   ├── handTracker.js          ห่อ MediaPipe HandLandmarker
│   ├── camera.js               จัดการกล้องหน้า/หลัง
│   ├── sentence.js             รวมผลทายรายเฟรมให้เป็นประโยค
│   ├── storage.js              เก็บข้อมูลลง IndexedDB
│   └── transfer.js             นำข้อมูลเข้า-ออกเป็นไฟล์ JSON
├── vendor/                     MediaPipe ฉบับเว็บ (เก็บไว้ในเครื่องเพื่อให้ทำงานออฟไลน์)
├── models/hand_landmarker.task โมเดลตรวจจับมือ 7.8 MB
└── icons/                      ไอคอนแอป (สร้างใหม่ด้วย `run icons`)
```

## ข้อควรระวังสำหรับคนแก้โค้ดต่อ

**1. แก้ `features.js` ต้องแก้ `src/features.py` ให้ตรงกันเสมอ**

ถ้าไม่ตรงกัน ข้อมูลจากสองฝั่งจะใช้ร่วมกันไม่ได้ โดยไม่มี error ฟ้องเลย
โมเดลจะแค่แม่นยำต่ำลงอย่างอธิบายไม่ถูก ซึ่งหาสาเหตุยากมาก ตรวจด้วย:

```bash
run parity
```

**2. แก้ไฟล์ใน `app/` ต้องเพิ่มเลข `CACHE_VERSION` ใน `sw.js`**

ไม่งั้นเบราว์เซอร์จะยังเสิร์ฟไฟล์เก่าจากแคชต่อไป และคุณจะงงว่าทำไมแก้แล้วไม่เปลี่ยน

**3. เรื่องภาพกระจกกับกล้องหน้า/หลัง**

กล้องหน้าแสดงภาพแบบกระจกเงา ส่วนกล้องหลังไม่กระจก ทำให้ข้อมูลที่เก็บด้วยกล้องหน้า
กับที่ใช้งานด้วยกล้องหลังกลับด้านกัน ระบบแก้ปัญหานี้ด้วยการ **เพิ่มข้อมูลแบบกลับด้าน
ตอนเทรนเสมอ** (`mirrorFeatureVector`) โมเดลจึงเห็นทั้งสองแบบและใช้มือข้างไหนก็ได้
ห้ามปิดการเพิ่มข้อมูลส่วนนี้
